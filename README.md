# deckwright

Читает произвольный `.pptx` как набор правил дизайн-системы и собирает по нему
новые слайды: три варианта вёрстки на одном контенте, нативные объекты в
`.pptx`, встроенный аудит качества, экспорт в `.pdf` и `.html`.

Кейс VK Tech «Цифровой дизайнер презентаций», ЛЦТ 2026.

## Статус

Работает целиком: разбор шаблона, приём входа в любом виде, план, три
варианта вёрстки, аудит с выбором исправлений, экспорт `.pptx`, `.pdf`,
`.html`, веб-интерфейс. Проверено на трёх шаблонах датасета, трёх holdout и
двух синтетических; живая модель — из GitHub Actions (`llm-probe.yml`).

| требование ТЗ | где |
|---|---|
| разбор шаблона, композиции, шрифты, декор | `src/deckwright/parse/` |
| структура колоды по брифу | `content/`, `plan/`, агенты `ingest_content`, `plan_deck` |
| графики и таблицы — `c:chart`, `a:tbl`; схемы — фигуры шаблона | `visuals/`, `docs/ARCHITECTURE.md` («Схемы — фигуры шаблона, а не SmartArt») |
| три варианта, одна ось различий | `configs/variants/`, `docs/ARCHITECTURE.md` |
| аудит, выбор исправлений пользователем | `audit/`, `app/ui.py`, `docs/AUDIT.md` |
| агенты и промпты — версионируемые файлы, версии в манифесте | `agents/`, `prompts/` |
| колода за 5 минут вместе с разбором входа | run 35: 5 пар из 6 — 157–300 с, sales × vk_tech — 412 с (задержки провайдера); `progress/handoff.md` |
| наборы для сдачи: 2 входа × 3 шаблона × 3 варианта | `outputs/demo/observability/`, `outputs/demo/sales/` |

Не сделано: генерация изображений (заложен интерфейс `image_provider`,
выключен), нативный SmartArt (сознательно — см. ARCHITECTURE), видео-демо.
Журнал — `progress/handoff.md`.

## Возможности

- Разбирает произвольный `.pptx` как дизайн-систему: токены цвета и
  типографики, layout'ы, композиции слайдов, повторители, декор, шрифты
  (включая встроенные в файл).
- Принимает материалы в любом виде — бриф строкой и файлы `txt`, `md`,
  `docx`, `pdf`, `pptx`, `json` — и приводит их к контент-пакету с проверкой
  каждого числа по тексту входа.
- Планирует колоду на 10–15 слайдов: намерение слайда, заголовок-вывод,
  блоки, данные.
- Верстает три варианта на одном контенте (`dense`, `balanced`, `airy`),
  клонируя композиции из слайдов-доноров шаблона.
- Пишет нативные объекты: графики `c:chart`, таблицы `a:tbl`, схемы —
  фигурами шаблона.
- Выбирает цвет текста по фактическому фону под ним (заливка, градиент,
  карточка, фон-картинка) с порогом контраста 4.5:1 и защищает логотипы и
  оформление шаблона от наложения текста.
- Проверяет результат: детерминированный аудит по IR и контекстный по
  картинке слайда, с выбором исправлений человеком.
- Экспортирует `.pptx`, `.pdf` (LibreOffice) и `.html`.

## Стек

Python 3.11+ · python-pptx + lxml (OOXML) · fontTools (метрики текста) ·
Pydantic (контракты слоёв) · Pillow · pdfplumber, python-docx (разбор входа) ·
OpenAI-совместимый клиент к модели с открытыми весами · Streamlit
(веб-интерфейс) · LibreOffice headless (`pptx` → `pdf`) · poppler
(`pdf` → `png`) · pytest, ruff · Docker / Docker Compose.

Фронтенда и бэкенда как отдельных сервисов в проекте нет: интерфейс —
Streamlit-приложение (`app/ui.py`), работающее с теми же слоями, что и CLI.

## Архитектура

```
бриф + файлы ─►[0 content]─► ContentPack  факты, ряды, цитаты; числа сверены с входом
template.pptx ─►[1 parse ]─► TemplateSpec  токены, layouts, паттерны, шрифты, декор
ContentPack  ─►[2 plan  ]─► DeckPlan      слайды: намерение, заголовок-вывод, блоки, данные
Spec+Plan+strategy ─►[3 layout]─► SlideIR  абсолютные боксы, стили из токенов, provenance
SlideIR ─►[4 render]─► .pptx ─► .pdf ─► .png ; .html
SlideIR+.pptx+.png ─►[5 audit]─► Issue[] ─► UI ─► выбранные ─►[fix]─► 3→4→5
```

Каждый слой — пакет с одним входом, одним выходом и Pydantic-контрактом в
`schemas/`; связывает их только `pipeline.py`. `SlideIR` — единый источник
истины для всех форматов экспорта и для детерминированного аудита. Подробно —
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Системные зависимости

Список один на все окружения — `scripts/install-system-deps.sh` (Debian/Ubuntu,
он же используется в образе и в CI): LibreOffice Impress, poppler, `libeot0`,
метрические клоны шрифтов.

На macOS пакеты ставятся своими именами (`brew install --cask libreoffice`,
`brew install poppler font-carlito font-caladea font-liberation`). Отдельного
внимания требует **libeot**: платформа её поддерживает — библиотека собирается
из исходников обычным C-компилятором, — но формулы в Homebrew нет и с
LibreOffice для macOS она не приезжает, поэтому по умолчанию приложению она
недоступна. Собранную библиотеку достаточно указать переменной
`DECKWRIGHT_LIBEOT` (см. `.env.example`); имя файла в стандартных путях
(`libeot.0.dylib`, `libeot.so.0`) подбирается само. Без неё встроенный в
шаблон шрифт не извлекается, текст меряется по подставленному, и это
попадает в манифест прогона. Что найдено, а что нет, показывает
`deckwright doctor`.

## Установка

Требуется Python 3.11+ и системные зависимости из раздела выше.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"        # без [dev] — без pytest, ruff и генератора фикстур
deckwright doctor              # что из системных зависимостей на месте
```

## Переменные окружения

Секреты живут только в `.env`; в `configs/config.yaml` — ссылки `${VAR}`.
Шаблон со всеми переменными и пояснениями — `.env.example`:

```bash
cp .env.example .env           # затем впишите свои endpoint и ключ
```

| переменная | зачем |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | OpenAI-совместимый endpoint модели: разбор входа, план, исправления |
| `VLM_BASE_URL`, `VLM_API_KEY`, `VLM_MODEL` | контекстный аудит по картинке слайда; может быть тот же endpoint |
| `T2I_BASE_URL`, `T2I_API_KEY`, `T2I_MODEL` | генерация изображений: интерфейс заложен, по умолчанию выключен |
| `DECKWRIGHT_LIBEOT` | путь к libeot, если она вне путей линковщика (обычно не нужна) |
| `DECKWRIGHT_PASSWORD` | пароль на вход в веб-интерфейс; пусто — вход открыт |
| `DECKWRIGHT_ENV_FILE` | другой путь к файлу переменных вместо `.env` в корне |
| `DECKWRIGHT_TEMPLATES` | каталог `.pptx` для тестов разбора шаблонов |

`.env` читает само приложение — ни `source`, ни docker-compose для этого не
нужны. Переменная, уже заданная в окружении, сильнее файла.

## Запуск

```bash
deckwright doctor                       # проверить системные зависимости
deckwright run \
  --config configs/config.yaml \
  --template путь/к/шаблону.pptx \
  --content отчёт.docx \
  --input таблица.pdf \
  --brief "Пара предложений: что показываем и кому" \
  --purpose project \
  --variant balanced                    # без флага — все три варианта
```

Материалы — в любом виде, по отдельности или вместе: текст брифа (`--brief`)
и файлы `txt`, `md`, `docx`, `pdf`, `pptx`, `json` (`--content`, `--input`,
сколько угодно). JSON в нашей схеме контент-пакета берётся как есть; всё
остальное, включая JSON чужой структуры, модель приводит к контент-пакету
(слой `content/`, промпт `prompts/ingest_content.v1.yaml`). Числа ответа
сверяются с текстом входа: факт или ряд с числом, которого во входе нет,
отбрасывается. Короткий бриф без данных даёт колоду без цифр. Сколько
слайдов — 10–15 — решает планировщик по объёму материала, если число не
задано в `deck.slide_count`.

Без ключа модели прогон идёт по записанным ответам: добавьте
`--recorded tests/fixtures/recorded` (только для готового контент-пакета —
разобрать новый вход без модели нельзя).

Бюджет — **пять минут на всю колоду**: разбор входа и генерация трёх
вариантов вместе. Последняя строка вывода и
`outputs/<прогон>/run-summary.json` показывают составляющие:

```
[прогон] разбор входа 21.4с (из них материалы 19.8с); генерация вариантов (3) 231.0с; всего 252.4с из 300с (в бюджете)
```

## Веб-интерфейс

```bash
streamlit run app/ui.py        # или docker compose up --build
```

Идущий прогон можно **отменить**: новых задач он не поставит, а ответ, который
придёт после отмены, не опубликует. Уже отправленный запрос к модели
остановить нельзя — он оплачен, и обещать обратное интерфейс не будет.

Экспорт трёх вариантов идёт параллельно (`render.max_parallel_conversions`,
по умолчанию 3, но не больше половины ядер машины). Замер на 8 ядрах: 21,4 с
при одном процессе, 15,6 с при двух, 10,2 с при трёх.

`.env` подхватывается сам — `source` не нужен. Прогон каждого пользователя
живёт в своём каталоге `outputs/<run_id>/` (входы, варианты, диагностика) и
виден только той вкладке, где запущен: ссылка на чужой прогон ничего не
открывает. Если LibreOffice недоступен, `.pptx` и `.html` всё равно
собираются и скачиваются, а про PDF интерфейс говорит прямо и предлагает
повторить **только экспорт**, без перегенерации колоды. Что из зависимостей
блокирует работу, а что отключает одну функцию, показывает
`deckwright doctor`.

Сценарий: загрузить шаблон, вписать бриф или вставить текст и/или приложить
материалы (txt, md, docx, pdf, pptx, json), выбрать назначение, указать
выступающего, выбрать варианты и нажать «Собрать». Что сервис понял из
входа — тема, факты, ряды и что отброшено сверкой чисел — показано над
вкладками вариантов. Прогон идёт в фоне, его номер остаётся в адресе — страницу
можно обновить, не потеряв результат. Находки аудита показаны рамками поверх
слайда; номер рамки совпадает с номером в списке. Отмеченное применяется
кнопкой, после чего колода пересобирается и проверяется заново, а что
применить не удалось — перечислено с причиной.

## Docker

```bash
docker compose up --build      # веб-интерфейс на http://localhost:8501
```

Образ (`Dockerfile`) ставит системные зависимости тем же
`scripts/install-system-deps.sh`, что и CI. Переменные берутся из `.env`
(`env_file`), артефакты прогонов остаются в `./outputs`, кэш разобранных
шаблонов — в именованном томе. Деплой на Railway — `railway.json` и
[`docs/DEPLOY.md`](docs/DEPLOY.md).

## Тесты и проверки

```bash
ruff check .                   # линтер   (обязательный гейт)
pytest -q                      # тесты    (обязательный гейт)
pytest -q tests/test_layout.py # один файл
```

Тестам, которым нужен LibreOffice или каталог шаблонов, без них проставляется
`skip`; остальные идут всегда. Живая модель в тестах не вызывается: ответы
записаны в `tests/fixtures/recorded/`.

## База данных и API

Базы данных в проекте нет — значит, нет ни миграций, ни дампов: состояние
прогона лежит файлами в `outputs/<run_id>/`. HTTP API проект не публикует:
точки входа две — CLI `deckwright` и Streamlit-интерфейс. Наружу проект
обращается сам, к OpenAI-совместимому endpoint'у модели.

## Ограничения

- Вход — только `.pptx` и `.potx`. PDF, Keynote и Google Slides напрямую не
  принимаются.
- Только десктопные браузеры. Сценарий проверен живым прогоном в **Chromium**;
  Firefox, Safari и Яндекс Браузер в среде разработки отсутствуют и не
  проверены.
- Сервис не является редактором слайдов: он показывает найденные проблемы и
  чинит выбранные, но не даёт двигать блоки руками.
- Если встроенный в шаблон шрифт распаковать не удалось, подставляется
  метрически близкий; факт подстановки пишется в манифест прогона и в аудит.
- Если в шаблоне нет ни одного примера графика, форма графика будет наша, а
  цвета и типографика — шаблона. Это отражается в отчёте аудита.
- Генерация требует внешнего endpoint'а модели: GPU локально не нужен, но без
  доступа к модели работает только разбор шаблона.
