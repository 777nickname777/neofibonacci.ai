# deckwright

Читает произвольный `.pptx` как набор правил дизайн-системы и собирает по нему
новые слайды: три варианта вёрстки на одном контенте, нативные объекты в
`.pptx`, встроенный аудит качества, экспорт в `.pdf` и `.html`.

Кейс VK Tech «Цифровой дизайнер презентаций», ЛЦТ 2026.

## Статус

В разработке. Пройдены фазы 0–11: пайплайн, аудит с циклом исправления и
веб-интерфейс. См. `progress/handoff.md`.

## Запуск

```bash
deckwright doctor                       # проверить системные зависимости
deckwright run \
  --config configs/config.yaml \
  --template путь/к/шаблону.pptx \
  --content отчёт.docx \
  --input таблица.pdf \
  --brief "Пара предложений: что показываем и кому" \
  --purpose project \
  --variant balanced                    # без флага — все три варианта
```

Материалы — в любом виде, по отдельности или вместе: текст брифа (`--brief`)
и файлы `txt`, `md`, `docx`, `pdf`, `pptx`, `json` (`--content`, `--input`,
сколько угодно). JSON в нашей схеме контент-пакета берётся как есть; всё
остальное, включая JSON чужой структуры, модель приводит к контент-пакету
(слой `content/`, промпт `prompts/ingest_content.v1.yaml`). Числа ответа
сверяются с текстом входа: факт или ряд с числом, которого во входе нет,
отбрасывается. Короткий бриф без данных даёт колоду без цифр. Сколько
слайдов — 10–15 — решает планировщик по объёму материала, если число не
задано в `deck.slide_count`.

Без ключа модели прогон идёт по записанным ответам: добавьте
`--recorded tests/fixtures/recorded` (только для готового контент-пакета —
разобрать новый вход без модели нельзя).

Бюджет — **пять минут на всю колоду**: разбор входа и генерация трёх
вариантов вместе. Последняя строка вывода и
`outputs/<прогон>/run-summary.json` показывают составляющие:

```
[прогон] разбор входа 21.4с (из них материалы 19.8с); генерация вариантов (3) 231.0с; всего 252.4с из 300с (в бюджете)
```

## Веб-интерфейс

```bash
streamlit run app/ui.py        # или docker compose up --build
```

Сценарий: загрузить шаблон, вписать бриф или вставить текст и/или приложить
материалы (txt, md, docx, pdf, pptx, json), выбрать назначение, указать
выступающего, выбрать варианты и нажать «Собрать». Что сервис понял из
входа — тема, факты, ряды и что отброшено сверкой чисел — показано над
вкладками вариантов. Прогон идёт в фоне, его номер остаётся в адресе — страницу
можно обновить, не потеряв результат. Находки аудита показаны рамками поверх
слайда; номер рамки совпадает с номером в списке. Отмеченное применяется
кнопкой, после чего колода пересобирается и проверяется заново, а что
применить не удалось — перечислено с причиной.

## Ограничения

- Вход — только `.pptx` и `.potx`. PDF, Keynote и Google Slides напрямую не
  принимаются.
- Только десктопные браузеры. Сценарий проверен живым прогоном в **Chromium**;
  Firefox, Safari и Яндекс Браузер в среде разработки отсутствуют и не
  проверены.
- Сервис не является редактором слайдов: он показывает найденные проблемы и
  чинит выбранные, но не даёт двигать блоки руками.
- Если встроенный в шаблон шрифт распаковать не удалось, подставляется
  метрически близкий; факт подстановки пишется в манифест прогона и в аудит.
- Если в шаблоне нет ни одного примера графика, форма графика будет наша, а
  цвета и типографика — шаблона. Это отражается в отчёте аудита.
- Генерация требует внешнего endpoint'а модели: GPU локально не нужен, но без
  доступа к модели работает только разбор шаблона.
